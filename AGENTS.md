# bpaf-kit: contributor and agent guide

Batteries for Rust command-line tools built on
[bpaf](https://docs.rs/bpaf): bpaf-kit (the library), bpaf-kit-macros
(`#[derive(Cli)]`) and bpaf-kit-build (a dependency-free `build.rs`
helper), published together at one version. Other projects depend on these
crates, so public APIs stay small, documented and stable. CONTRIBUTING.md
covers the pull request flow and releases.

## Commands

Use the nix dev shell. It pins rustc (see `rust-toolchain.toml`) and
provides cargo-nextest and cargo-deny:

```sh
nix develop -c cargo fmt --all --check
nix develop -c cargo clippy --workspace --all-targets -- -D warnings
nix develop -c cargo clippy --workspace --all-targets --all-features -- -D warnings
nix develop -c cargo clippy -p bpaf-kit --all-targets --no-default-features -- -D warnings
nix develop -c cargo nextest run --workspace --all-features
nix develop -c cargo test -p bpaf-kit --no-default-features
nix develop -c cargo test --workspace --all-features --doc
RUSTDOCFLAGS="-D warnings" nix develop -c cargo doc --workspace --no-deps --all-features
nix develop -c cargo deny check
nix develop -c cargo publish --workspace --dry-run --allow-dirty
nix build .#demo && ./result/bin/demo --version --verbose
```

Every change must pass fmt, clippy (with and without `--all-features`, and
bpaf-kit with `--no-default-features`), the tests (default features,
`--all-features`, `--no-default-features`), the doctests and the doc build.
Commit small, focused changes. Each crate's MSRV is its `rust-version`:
the workspace default is 1.85 (bpaf-kit-macros, bpaf-kit-build), and
bpaf-kit and the demo override it with 1.88 (let chains). Keep the 1.85
crates free of let chains and other newer language features. CI's `msrv`
job builds and tests each crate on its own value.

## Layout

- `crates/bpaf-kit`: the library. Its README.md is the root README
  (symlink) and the crate docs (`include_str!`), so its examples run as
  doctests. Snippets that need a feature are wrapped in hidden
  `# #[cfg(feature = "...")]` lines.
- `crates/bpaf-kit-macros`: `#[derive(Cli)]`, re-exported as
  `bpaf_kit::Cli`.
- `crates/bpaf-kit-build`: the dependency-free `build.rs` helper.
- `examples/demo`: a CLI using every module (not published);
  `tests/cli.rs` are the end-to-end tests.
- `nix/with-version-file.nix`: the version-file wrapper; `flake.nix`
  exports it as `lib.withVersionFile` and builds `packages.demo` with it.

In `crates/bpaf-kit/src`:

- `lib.rs`: `App` (the startup sequence the derive calls: interrupt,
  `--man`, `--version`, parse, logging) and `color_enabled`.
- `cmd.rs`: `Cmd`, `Redirect`, `Output`, the coded `Error`, and the global
  echo/dry-run flags (`BPAF_KIT_ECHO`, `BPAF_KIT_DRY_RUN`).
- `version.rs`: `BuildInfo`, `build_info!`, and the runtime override file
  (`<NAME>_VERSION_FILE` or `../share/<name>/version.env`).
- `suggest.rs`, `interrupt.rs`, and the feature-gated `table.rs`, `man.rs`,
  `log.rs`, `prompt.rs`.

## Conventions

- Library errors use thiserror, carry a stable snake_case `code()`, and
  derive `miette::Diagnostic` with the same code behind the `miette`
  feature (a test checks they match).
- Optional dependencies stay behind features; the core depends on bpaf,
  ctrlc, strsim and thiserror only. bpaf-kit-build has no dependencies.
- Code generated by `bpaf-kit-macros` refers to `::bpaf_kit::…` only, so
  users need no extra dependencies; anything feature-dependent goes through
  `App`, which compiles either way.
- Mind startup cost: nothing reads files or spawns processes on a normal
  start (the version file is read only for `--version`).
- No `unwrap` outside tests; `core`/`alloc` paths over `std` where they
  exist (clippy enforces both).
- Crate READMEs are crate docs (`include_str!`), so their examples must
  compile and pass. Keep their links absolute so they work on crates.io.
- Changelog entries come from commit messages (release-plz), so write
  commit subjects that read well in CHANGELOG.md.
